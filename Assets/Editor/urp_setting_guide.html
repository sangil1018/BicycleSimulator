1. 프로젝트 및 전역 그래픽 설정

그래픽의 기초 공사 단계입니다. 여기가 틀어져 있으면 뒤에서 아무리 조명을 다듬어도 사실감이 나오지 않습니다.

감마 공간에서는 빛의 감쇠와 혼합이 물리적으로 틀리게 계산됩니다. PBR의 대전제라 이것부터 확인하세요. 이미 진행 중인 프로젝트라면 변경 시 전체 룩이 바뀌므로 조명 재조정이 필요합니다.

URP Asset / Renderer

필수URP Asset — Quality (HDR · Render Scale · Upscaling)▶
메뉴 경로
URP Asset 선택 > Inspector > Quality
일반 기준값
HDR: 켬 / HDR Precision: 64 Bit / Render Scale: 1.0 (부하 시 0.8~0.9) Upscaling Filter: Spatial-Temporal Post-Processing (STP) / Anti Aliasing(MSAA): Disabled
이 프로젝트 확정
HDR: 켬 / HDR Precision: 32 Bit / MSAA: Disabled Render Scale: 2.0 (2× 슈퍼샘플링) / Upscaling Filter: 무관

HDR은 Bloom·ACES 톤매핑의 전제조건입니다. TAA를 쓸 때 MSAA는 비용만 늘고 이점이 적으니 끄는 편이 낫습니다.

Render Scale 2.0은 지글거림(스페큘러 시머·에지 알리아싱)을 잡기 위해 의도적으로 택한 2× 슈퍼샘플링입니다. 1.0에서는 TAA만으로 부족했습니다. 픽셀 수는 4배지만 고정 설치물이라 프레임 예산으로 감당하는 선택입니다.

Render Scale이 1을 넘으면 Upscaling Filter가 무시됩니다. URP는 renderScale > 1.0일 때 imageScalingMode를 Downscaling으로 잡고 업스케일 경로를 통째로 건너뜁니다. 즉 STP·FSR은 이 설정에서 동작하지 않으며 순수한 다운샘플만 수행됩니다. 프레임이 부족해지면 Render Scale 1.0 + STP로 전환하는 것이 다음 카드입니다.

또한 인스펙터 슬라이더 상한은 2.0이지만 URP는 이 값을 클램프 없이 scaledWidth = pixelWidth × renderScale로 사용합니다. 직렬화 파일을 직접 편집하면 3 이상도 들어가며(과거 이 에셋에 3이 들어가 있었음), 씬 뷰는 렌더 스케일이 무시되어 에디터에서는 증상이 보이지 않습니다. 반드시 슬라이더로만 조정하세요.

Max Distance는 화질과 비용을 동시에 좌우하는 최대 변수입니다. 무작정 늘리지 말고 카메라가 실제로 닿는 범위로 조이세요. 그림자 끝단이 끊겨 보이면 Distance를, 표면에 줄무늬(섀도 아크네)가 생기면 Bias를 조정합니다.

자전거 주행이라 시야가 멀리 가서 100m가 필요하지만, 프레임이 부족해지면 여기가 1순위 절감 대상입니다. Max Distance를 절반으로 줄이면 같은 4096 해상도로 4배 촘촘한 그림자를 얻습니다.

Forward+는 오브젝트당 조명 제한(4~8개)을 없애고, GPU Resident Drawer의 전제 조건이기도 합니다. Deferred+도 GPU Resident Drawer와 호환되지만 반투명·머티리얼 다양성에서 Forward+가 무난합니다.

필수Depth / Opaque Texture 버퍼링▶
메뉴 경로

추천 설정
Depth Texture: 켬 / Opaque Texture: 켬 (굴절·반투명 효과 필요 시) / Opaque Downsampling: None

SSAO·SSR·포그 등 화면 공간 효과가 깊이 버퍼를 요구합니다. Depth Texture가 꺼져 있으면 효과가 조용히 동작하지 않으니 먼저 확인하세요. SSAO의 Depth Normals 소스를 쓰면 노멀 프리패스가 추가로 필요합니다.

파이프라인 선택 참고 — 레이 트레이싱, 네이티브 볼류메트릭 포그, 물리 광량 단위(Lux/Lumen)까지 필요한 극한의 사실감이 목표라면 HDRP가 정공법입니다. URP는 이 문서의 기법들로 HDRP에 근접할 수 있지만 일부는 서드파티나 커스텀으로 메꿔야 합니다. 데스크톱 고정 사양 설치물이면서 위 기능이 핵심이라면 초기 단계에서 HDRP 전환을 한 번 저울질해 보세요.

2. 빛의 시뮬레이션: GI · 화면 공간 효과 · 공기감

공간 전체의 거시적인 빛(GI)과 미세한 디테일(SSAO·SSR), 그리고 공기감(포그)을 겹겹이 쌓아 현실감을 부여합니다.

APV (Adaptive Probe Volumes)

APV는 조도를 '공중의 3D 격자'에 저장하고, 셰이더가 픽셀의 월드 좌표에서 그 격자를 보간해 읽습니다. 라이트맵처럼 표면에서 직접 계산하는 방식이 아니라는 점이 모든 아티팩트의 출발점입니다. 아래 항목들은 Unity 6.3 / SRP 17.3 패키지 소스를 직접 확인해 정리했습니다.
필수APV 활성화 & 볼륨 배치2022.2+▶
메뉴 경로
① Project Settings > Graphics > Pipeline Specific Settings > URP > Light Probe System = Probe Volumes ② GameObject > Light > Adaptive Probe Volume ③ Window > Rendering > Lighting > Adaptive Probe Volumes 탭 > Generate Lighting
추천 설정
Light Probe System: Probe Volumes / 볼륨은 실제로 오브젝트가 있는 구역만 덮도록 배치 Fill Empty Spaces: 해제 / Y 범위가 지하·육교까지 포함하는지 확인

볼륨 바깥은 데이터가 아예 없어 검거나 평평하게 렌더되므로 씬 경계와 높이 범위를 먼저 확인하세요. Fill Empty Spaces를 켜면 빈 공중까지 프로브를 채워 메모리만 낭비합니다.

필수Probe Placement (Min Probe Spacing / Simplification Levels)▶
메뉴 경로
Window > Rendering > Lighting > Adaptive Probe Volumes 탭 > Baking Set > Probe Placement (또는 Project 창에서 '<씬이름> Baking Set' 에셋 선택)
Level2 기준
Min Probe Spacing: 1m / Simplification Levels: 3 Probe Volume 쪽 Override Subdivision Levels 켜고 0~2 (81m 브릭 배제) 값을 바꾼 뒤 반드시 Generate Lighting 재실행

최소 브릭 크기 = Min Probe Spacing × 3, 셀 크기 = 3(Simplification Levels) 브릭, 서브디비전 단계 = Levels + 1 입니다. 1m / 3단계면 서브디비전 0~3단계가 생기고 브릭 크기는 3 / 9 / 27 / 81m, 각각 프로브 간격 1 / 3 / 9 / 27m 입니다.

서브디비전 레벨은 숫자가 클수록 '브릭이 큰' 쪽입니다 (BrickSize = minBrickSize × 3^level). Level2는 볼륨 3개 모두 Override를 켜고 상한을 2로 잡아 가장 성긴 81m 브릭을 배제했습니다. 즉 프로브를 줄이는 설정이 아니라 늘리는 설정입니다.

또 하나: 인스펙터에 보이는 값과 실제로 구워진 값(bakedMinDistanceBetweenProbes)은 별개입니다. 재베이크 전까지는 예전 격자가 그대로 쓰이므로, 값만 고쳐두고 "왜 안 바뀌지" 하는 상황이 흔합니다. 2m 격자로는 도로·인도 폭의 명암을 표현할 수 없어 검은 띠가 남습니다.
필수Probe Dilation — Validity Threshold는 UI가 반전됨▶
메뉴 경로
Lighting > Adaptive Probe Volumes 탭 > Baking Set > Probe Dilation Settings
Level2 기준
Dilation: 켬 / Validity Threshold: 0.75(UI) / Search Radius: 1.5 Dilation Iterations: 1 / Squared Distance Weighting: 켬 → 검은 얼룩이 남으면 Iterations만 2로 (범위 1~5)
UI 슬라이더는 내부 저장값의 반전(1 − x)입니다. UI 0.75 = 내부 0.25이고, 값이 클수록 "더 쉽게 무효로 판정해 이웃 값으로 교체"합니다. UI를 0.25처럼 낮게 두면 지오메트리에 75% 이상 파묻힌 프로브만 교체되고, 25~75%로 애매하게 묻힌 프로브는 어두운 값 그대로 남아 도로·벽 표면에 검은 띠를 만듭니다.

Virtual Offset의 Validity Threshold에도 같은 반전이 적용되므로 두 값을 UI 기준 0.75로 맞춰두면 서로 어긋나지 않습니다. Search Radius는 에디터가 Min Probe Spacing 미만으로 내려가지 않게 자동으로 잡아줍니다.

권장Virtual Offset Settings▶
메뉴 경로
Lighting > Adaptive Probe Volumes 탭 > Baking Set > Virtual Offset Settings
Level2 기준
Virtual Offset: 켬 / Validity Threshold 0.75(UI) / Search Distance Multiplier 0.2 Geometry Bias 0.01 / Ray Origin Bias −0.001 (전부 6.3 기본값) → 두꺼운 바닥·슬래브에 갇힌 프로브가 남으면 Search 0.5 / Geometry Bias 0.05 로

지오메트리 안에 박힌 프로브를 표면 밖으로 밀어냅니다. Dilation보다 결과가 좋지만 베이크 시간이 늘어납니다. Search Distance Multiplier는 브릭 크기에 대한 비율이라 기본 0.2로는 도로 슬래브처럼 두꺼운 바닥에 갇힌 프로브를 빼내지 못합니다. Geometry Bias 0.01(1cm)은 면에 너무 붙어 밀어낸 뒤에도 다시 자기 자신에 가려집니다.

필수Adaptive Probe Volumes Options (Volume Override)▶
메뉴 경로
Global Volume > Volume Profile > Add Override > Lighting > Adaptive Probe Volumes Options
일반 기준값 (6.3 기본)
Normal Bias 0.05 / View Bias 0.1 / Leak Reduction Mode: Quality
이 프로젝트 확정
Normal Bias 0.33 / View Bias 0 / Leak Reduction Mode: Performance Sampling Noise 0.1 + Animate 켬 / Min Valid Dot Product: 무시 (6.3에서 폐기)

베이크 없이 즉시 반영되는 유일한 APV 항목이라 문제 진단 시 가장 먼저 시험해볼 값들입니다.

이 프로젝트는 6.3 기본값과 다른 조합을 씁니다. 동적 오브젝트의 컬러 얼룩을 이 값들로 잡으려 했지만 실제 원인은 Disk Streaming이었고(아래 항목 참조), 그것을 해제한 뒤로는 Normal Bias 0.33에서도 문제가 없어 야외 도시 씬에 맞게 그대로 유지하기로 했습니다. Leak Reduction도 Performance로 충분합니다.

다만 원리는 알아두세요. Normal Bias는 샘플 지점을 노멀 방향으로 밀어내므로 값이 크면 얇은 벽·바닥을 뚫고 반대편 프로브를 읽습니다. 실내나 좁은 통로가 추가되어 빛이 새거나 곡면에 색이 갈라지면 여기부터 0.05까지 내리고 Leak Reduction을 Quality로 올리세요.

Min Valid Dot Product Value는 6000.0에서 [Obsolete] 처리되어 프로파일에 값이 남아 있어도 아무 동작을 하지 않습니다. 튜닝 대상에서 제외하세요.
선택Sky Occlusion — 고정 하늘이면 끄기Unity 6▶
메뉴 경로
Lighting > Adaptive Probe Volumes 탭 > Baking Set > Sky Occlusion Settings
Level2 기준
Sky Occlusion: 해제 — 이 프로젝트는 스카이박스를 런타임에 바꾸지 않으므로 이득 없음 → 시간대 기능을 넣게 되면 Samples 2048, Bounces 2, Albedo Override 0.6, Sky Direction 켬

하늘이 바뀔 때 씬을 다시 라이팅하기 위한 기능입니다. 스카이박스를 교체하지 않는 씬에서는 베이크 시간과 메모리만 소모합니다.

게다가 지오메트리에 묻힌 프로브는 하늘 가시성이 0으로 구워지고 그 값이 앰비언트에 곱해지므로, '조금 어두움'이 아니라 완전한 검정이 됩니다. 검은 면 문제를 추적할 때 한 번 꺼보면 원인 분리가 쉽습니다. 끄고 확보한 메모리로 SH Bands를 L2로 올리는 편이 화질 이득이 큽니다.

필수Disk Streaming — 동적 오브젝트 컬러 아티팩트의 원인이 프로젝트에서 재현·확정▶
메뉴 경로
URP Asset > Inspector > Lighting > Probe Volumes > Enable Disk Streaming
이 프로젝트 확정
Enable Disk Streaming: 해제 (필수) / Enable GPU Streaming: 켬 유지 가능
Disk Streaming을 켜면 보행자·차량 같은 동적 오브젝트 표면에 빨강·녹색 얼룩이 번집니다. 셀 데이터가 부분 로드되면서 프로브 값이 깨지는 것으로 보이며, 해제하면 즉시 사라집니다.

2026-08-09 이 프로젝트에서 확정된 원인입니다. SH L2 전환, Indirect Multiplier 정상화, 프로브 밀도 1m 재베이크로도 해결되지 않았고 오직 Disk Streaming 해제만이 효과가 있었습니다. Unity 포럼에도 APV 블록형 아티팩트가 Disk/GPU Streaming 해제로 해결된 동일 사례가 보고돼 있습니다.

APV 색 이상이 재발하면 Normal Bias나 Leak Reduction보다 이 설정을 먼저 의심하세요. 대신 셀이 전량 메모리에 상주하므로 Memory Budget(2048MB) 초과 여부를 함께 봐야 합니다.

메뉴 경로
GameObject > Light > Probe Adjustment Volume
추천 설정
검은 구역: Override Validity Threshold 또는 Override Virtual Offset Settings 최후 수단: Invalidate Probes, Intensity Scale / 밀도 보강은 이걸로 안 됨

전역 베이크 설정을 흔들지 않고 문제 구역만 고치는 도구입니다. 6.3의 모드는 Invalidate Probes · Override Validity Threshold · Apply Virtual Offset · Override Virtual Offset Settings · Override Sky Direction · Override Sample Count · Override Rendering Layer Mask · Intensity Scale 입니다.

이 컴포넌트는 프로브 '밀도'를 바꾸지 못합니다. 특정 구역만 촘촘하게 하려면 그 구역에 Adaptive Probe Volume을 하나 더 만들고 Override Subdivision Levels를 켜세요.
필수Receive GI 선택 기준 — 라이트맵 vs 프로브▶
메뉴 경로
MeshRenderer > Inspector > Lighting > Receive Global Illumination 일괄 적용: Tools > Asset Tools > 라이팅 프리셋
추천 설정
도로·바닥·벽·간판 등 얇거나 넓은 면 → Lightmaps 나무·프롭·차량 등 부피 있는 것 → Light Probes Light Probes를 고를 땐 Renderer의 Light Probes 드롭다운이 Off가 아닌지(Blend Probes) 반드시 확인

라이트맵은 표면 텍셀마다(해상도 20이면 약 5cm) 계산하고, APV는 1~2m 공중 격자를 픽셀 위치에서 보간합니다. 양면이 서로 다른 조명 환경에 접한 얇은 면은 샘플 지점이 반대편으로 넘어가 검은 띠가 생기며, 이건 어떤 APV 설정으로도 완전히 없앨 수 없습니다. 판단 기준은 '면적'이 아니라 '두께와 폐색 관계'입니다.

Receive GI를 Light Probes로 바꿔도 Renderer의 Light Probes 드롭다운이 Off면 APV를 아예 샘플링하지 않아 오브젝트가 새까맣게 나옵니다. 두 값은 별개 필드라 함께 맞춰야 합니다.
선택APV 메모리 / SH Bands▶
메뉴 경로
URP Asset > Inspector > Lighting > Probe Volumes (SH Bands · Memory Budget · Streaming)
이 프로젝트 확정
SH Bands: L2 / Memory Budget: High(2048) / Blending Budget: 256 GPU Streaming: 켬 / Disk Streaming: 해제

L1은 메모리가 절반이지만 방향성이 뭉개져, 프로브로 라이팅되는 오브젝트가 라이트맵 오브젝트 옆에서 평평하게 붕 떠 보입니다. 다만 Min Probe Spacing을 촘촘히 하면서 L2까지 켜면 예산을 넘겨 셀이 통째로 로드되지 않고, 그 구역이 또 검게 보입니다.

Disk Streaming은 위 별도 항목의 이유로 반드시 꺼둡니다. 끈 상태에서는 셀이 전량 상주하므로 예산 초과 감시가 더 중요해집니다.

전역 조명 (GI)

권장베이크 GI (Progressive GPU Lightmapper)▶
메뉴 경로
Window > Rendering > Lighting > Scene 탭 > Lightmapping Settings 대상 오브젝트: Inspector 우상단 Static 드롭다운 > Contribute GI
Level2 기준
Lightmapper: Progressive GPU / Resolution 20 texels / Max Size 2048 / Padding 2 Compression: High Quality / Samples Direct 32 · Indirect 128 · Environment 64 Bounces 3 (Min 2) / Denoiser: Optix (Direct·Indirect·AO 전부) / Filtering: Auto Directional Mode: Directional / Ambient Occlusion: 켬, Max Distance 1, Exponent 1

정적 설치물이라면 실시간 GI보다 베이크가 화질·프레임 모두 압도적으로 유리합니다. 대상 오브젝트는 Inspector 우상단 Static 드롭다운에서 Contribute GI를 켜야 라이트맵에 포함됩니다.

AO Max Distance는 Level1의 3에서 1로 낮춘 값입니다. 3m는 나무 캐노피 아래를 통째로 먹어버려 밑면이 새까맣게 나왔고, 런타임 SSAO와 이중으로 걸리는 문제도 있었습니다.

샘플 수(32/128/64)는 Level1(64/256/128)의 절반입니다. 노이즈가 보이면 Indirect부터 올리세요.

리프 카드는 라이트맵에 구우면 안 됩니다. 나무 캐노피는 알파컷 리프 카드 수십~수백 장인데, 해상도 20 texels/unit에 Padding 2면 카드 하나당 실질 텍셀이 한두 개뿐입니다. 그 값이 캐노피 내부의 가려진 지점 한 곳을 샘플한 결과라 사실상 검정이 찍히고, Directional 라이트맵의 단일 우세 방향까지 겹쳐 아랫면이 더 어두워집니다.

Level1 기준 2048 라이트맵이 110장 나왔으므로, 나무·프롭을 Light Probes로 돌려 장수를 줄이는 것이 베이크 시간과 메모리 양쪽에 가장 효과가 큽니다. 머티리얼 쪽은 Double Sided GI · Alpha Clip · Cull Off가 이미 맞아도 이 문제는 해결되지 않습니다.
권장Mixed Lighting 모드▶
메뉴 경로
Window > Rendering > Lighting > Scene 탭 > Mixed Lighting 라이트별 모드: Light 컴포넌트 > Mode
Level2 기준
Lighting Mode: Shadowmask / 씬의 유일한 광원 = Directional 1개 Mode: Mixed / Color (1, 0.99, 0.96) / Intensity 2.5 / Indirect Multiplier 1 Environment: Skybox 소스, Ambient Intensity 1.0, Fog 해제, Reflection Bounces 2

Shadowmask는 정적 그림자를 텍스처로 굽고 동적 오브젝트만 실시간 그림자를 받게 해 실시간 그림자 개수를 크게 줄입니다. Baked Indirect는 그림자가 전부 실시간이라 더 무겁지만 동적 변화에 자연스럽습니다. 설치물은 Shadowmask 권장.

APV와 함께 쓰면 프로브가 라이트별 차폐값(Probe Occlusion)까지 저장합니다. 라이트맵은 텍셀 단위로 그림자를 판정하지만 프로브는 브릭 단위라, 프로브로 라이팅되는 표면은 격자 경계를 따라 통째로 어두워지는 직선 경계가 생길 수 있습니다.

또한 Indirect Multiplier를 1보다 크게 올리면 바운스 표면의 알베도 색이 그만큼 증폭되어 프로브에 들어갑니다. 씬에 컬러 조명이 하나도 없어도 곡면(얼굴 등)에 색이 갈라져 보이는 원인이 될 수 있으니 1을 기본으로 두세요.

추천 설정

화면 공간 효과 (Renderer Feature)

필수SSAO (Screen Space Ambient Occlusion)▶
메뉴 경로
Renderer(Universal Renderer Data) 선택 > Inspector > Add Renderer Feature > Screen Space Ambient Occlusion
이 프로젝트 확정
Method: Interleaved Gradient / Source: Depth Normals / Intensity 1.0 / Radius 0.5 Direct Lighting Strength 0.221 / Falloff 30 / Samples: Medium(8) / Blur Quality: High(Bilateral) Downsample·After Opaque: 해제 → Render Scale 2.0(4배 픽셀)이므로 Medium 고정. Render Scale을 1.0으로 내리면 High(12)로 올릴 것

접촉면 그림자로 물체가 바닥에 "앉아 있는" 느낌을 만듭니다. Direct Lighting Strength를 높이면 직사광까지 어두워져 때가 낀 듯 인위적인 느낌이 나므로 낮게 유지하는 것이 사실감의 핵심입니다.

SSAO는 베이크 AO를 대체하지 못합니다. 베이크 AO는 캐노피 아래·골목 같은 대규모 폐색을, SSAO는 Radius 0.5m 범위의 접촉 음영만 담당합니다. 대규모 폐색은 SSAO Radius를 키워서가 아니라 APV·라이트맵의 간접광 자체로 해결해야 합니다 — Radius를 키우면 기둥·난간에 헤일로가 생기고 비용만 늘어납니다.

Source가 Depth Normals면 Normal Quality 필드는 비활성이며 사용되지 않습니다(노멀 프리패스에서 받아옴). After Opaque를 켜면 AO가 앰비언트가 아니라 최종 색에 곱해져 과하게 어두워지고 Direct Lighting Strength가 제대로 동작하지 않습니다.

픽셀 셰이더 부하가 있으니 카메라가 가까이 가는 핵심 표면에만 쓰세요. 값을 크게 올리면 실루엣 경계에서 텍스처가 미끄러지듯 흘러내리는 현상이 보입니다. 시선을 비스듬히 두고 확인하는 것이 검증 요령입니다.

4. 영화적 마감 및 포스트 프로세싱

디지털 렌더링 특유의 날것 느낌을 제거하고 영화 카메라 렌즈의 특성을 부여합니다. 대부분 Global Volume의 Override로 추가합니다.

Global Volume이 없다면 — GameObject > Volume > Global Volume으로 생성한 뒤, Inspector의 Profile 옆 New 버튼으로 프로파일을 만들고 Add Override로 아래 항목들을 추가합니다.

안티앨리어싱 / 업스케일

권장STP (Spatial-Temporal Post-Processing)Unity 6▶
메뉴 경로
URP Asset 선택 > Inspector > Quality > Upscaling Filter
추천 설정
Upscaling Filter: Spatial-Temporal Post-Processing 여유 있으면 Render Scale 1.0 유지 / 프레임 부족하면 0.7~0.85로 낮춰 활용

STP는 Render Scale이 1.0이어도 계속 동작하며 최종 렌더 출력에 TAA를 적용합니다. 즉 업스케일과 안티앨리어싱을 겸합니다. 저해상도 렌더에서 재구성 품질이 뛰어나 4K 디스플레이 설치물에서 프레임을 확보하는 가장 효과적인 수단입니다.

단, Render Scale이 1을 넘으면 STP는 동작하지 않습니다. URP는 renderScale > 1.0에서 imageScalingMode를 Downscaling으로 잡고 업스케일 경로를 건너뜁니다. 이 프로젝트는 현재 Render Scale 2.0(2× 슈퍼샘플링 + 일반 TAA)이라 STP가 비활성 상태입니다. 프레임이 부족해지면 Render Scale 1.0 + STP로 전환하는 것이 다음 카드입니다.
필수TAA (Temporal Anti-Aliasing)2022.2+▶
메뉴 경로

추천 설정
Anti-aliasing: Temporal Anti-aliasing / Quality: High / 잔상이 거슬리면 샤프닝 소량 병행

외곽선 계단은 물론 SSAO·SSR의 노이즈까지 시간축으로 뭉개줘 화질 향상 폭이 가장 큰 항목입니다. STP를 켠 경우 STP가 TAA 역할을 겸하므로 중복 설정하지 않아도 됩니다. 빠른 움직임에서 고스팅이 생길 수 있습니다.

5. 안정적인 프레임 방어를 위한 최적화

인터랙티브 환경에서 실시간 렌더링 부하와 외부 데이터 처리(OpenCV·뎁스 카메라 등)가 충돌할 때 해결하는 방법론입니다.

A. CPU 바운드 — 드로우콜 & 컬링

권장GPU Resident Drawer (3단계 설정)Unity 6▶
메뉴 경로

D. 설치물 운영 세팅

현장 사고 방지 — 아래 두 항목은 무인 운영 설치물에서 가장 흔한 장애 원인입니다. 빌드 전 반드시 확인하세요.
① Run In Background가 꺼져 있으면 포커스를 잃는 순간 콘텐츠가 정지합니다.
② 멀티 디스플레이는 Display.displays[i].Activate()를 호출하지 않으면 2번째 이후 화면이 검게 남습니다.
권장Target Frame Rate / VSync▶
메뉴 경로
Edit > Project Settings > Quality > Rendering > VSync Count (코드) Application.targetFrameRate = 60;
추천 설정
VSync Count: Every V Blank (디스플레이 60Hz 기준) / targetFrameRate는 주사율과 일치 VSync를 쓸 때 targetFrameRate는 -1로 두는 것이 충돌이 적음

전시장 디스플레이는 대부분 60Hz 고정입니다. 프레임을 그 이상 뽑아봐야 티어링과 발열만 늘어납니다. 프레임 상한을 걸어 GPU 여유를 남겨두면 인터랙션 순간의 스파이크를 흡수할 수 있습니다.

권장Player 빌드 / 해상도 설정▶
메뉴 경로
Edit > Project Settings > Player > Resolution and Presentation
추천 설정
Fullscreen Mode: Exclusive Fullscreen (성능 유리) 또는 Fullscreen Window (멀티 디스플레이 시) Run In Background: 켬 / Visible In Background: 켬 / Resizable Window: 해제

무인 운영 설치물은 Run In Background가 꺼져 있으면 포커스를 잃는 순간 멈춥니다. 다면 프로젝션이면 Exclusive Fullscreen이 오히려 방해가 되므로 Fullscreen Window를 씁니다.

선택멀티 디스플레이 / 프로젝터▶
메뉴 경로
카메라 선택 > Inspector > Output > Target Display (코드) Display.displays[i].Activate();
추천 설정
카메라별 Target Display 지정 / 시작 시 Display.displays 전체 Activate 호출 필수 베젤 보정·엣지 블렌딩은 별도 셰이더나 프로젝터 자체 기능 활용

빌드에서는 Activate()를 명시적으로 호출하지 않으면 2번째 이후 디스플레이가 검게 남습니다. 현장 셋업 전에 반드시 실제 다중 출력 환경에서 검증하세요.

선택Profiler / Memory Profiler▶
메뉴 경로
Window > Analysis > Profiler Memory Profiler는 Window > Package Manager에서 별도 설치
추천 설정
빌드에 연결해 측정 (에디터 수치는 부정확) / Development Build + Autoconnect Profiler Deep Profile은 원인을 좁힐 때만 / CPU · GPU · Memory 모듈 위주 확인

에디터에서의 프레임은 실제 빌드와 크게 다릅니다. 반드시 실측하세요. GPU 내부까지 파야 하면 RenderDoc을 병행합니다.
