# Asset Tools 메뉴(탭) 추가 방법

`Tools > Asset Tools` (Ctrl+Shift+T) 윈도우에 새 기능을 붙이는 방법입니다.

`AssetToolPage`를 상속하는 클래스를 이 폴더에 만들면 **자동으로 탭이 추가**됩니다.
`AssetToolsWindow`가 `TypeCache`로 상속 클래스를 전부 찾아 등록하므로 등록 코드는 건드릴 필요가 없습니다.

---

## 1. 최소 예제

`Assets/Editor/AssetTools/MyToolPage.cs`

```csharp
using UnityEditor;
using UnityEngine;

namespace AssetTools.Editor
{
    public class MyToolPage : AssetToolPage
    {
        public override string Title => "새 기능";   // 왼쪽 탭에 표시될 이름
        public override int Order => 20;             // 작을수록 위쪽 (콜라이더 삭제는 10)

        public override void OnGUI()
        {
            if (GUILayout.Button("실행"))
            {
                Debug.Log("실행됨");
            }
        }
    }
}
```

저장하고 Unity로 돌아가 컴파일되면 탭이 바로 나타납니다. (윈도우가 열려 있었다면 도메인 리로드 후 다시 만들어집니다)

### 지켜야 할 것

- 파일 위치는 **`Editor` 폴더 안**이어야 합니다 (`Assets/Editor/AssetTools/` 권장). 아니면 빌드에 포함되어 에러가 납니다.
- **매개변수 없는 기본 생성자**가 있어야 합니다. 없으면 콘솔에 경고가 뜨고 탭에서 제외됩니다.
- 네임스페이스는 `AssetTools.Editor`로 맞추는 게 편합니다. (다른 네임스페이스여도 동작은 합니다)

## 2. AssetToolPage 멤버

| 멤버 | 필수 | 설명 |
|---|---|---|
| `string Title` | O | 탭 이름 |
| `void OnGUI()` | O | 탭 내용 그리기. IMGUI(`EditorGUILayout`) 사용 |
| `int Order` | | 탭 정렬 순서. 기본 100, 작을수록 위 |
| `void OnEnable()` | | 윈도우가 열릴 때 1회. 초기 상태 계산용 |
| `void OnSelectionChanged()` | | 에디터 선택이 바뀔 때마다 호출. 선택 기반 툴이면 여기서 갱신 |
| `EditorWindow Window` | | 자기를 담고 있는 윈도우 (`Window.Repaint()` 등) |

상태(옵션 토글, 결과 문자열 등)는 그냥 클래스 필드로 두면 됩니다.
Unity를 껐다 켜도 유지하고 싶으면 `EditorPrefs`를 쓰세요.

```csharp
const string PrefKey = "AssetTools.MyTool.Option";

public override void OnEnable() => _option = EditorPrefs.GetBool(PrefKey, true);

// 값이 바뀐 시점에
EditorPrefs.SetBool(PrefKey, _option);
```

## 3. 선택한 오브젝트 다루기 (`AssetToolsSelection`)

씬 오브젝트와 프로젝트의 프리팹 에셋은 수정 방법이 다릅니다. 이 구분을 대신 처리해 주는 공용 헬퍼가 있습니다.

```csharp
// includeFolders: true면 Project 창에서 폴더를 선택했을 때 하위 폴더까지 훑어 프리팹을 전부 포함
SelectionResult selection = AssetToolsSelection.Resolve(includeFoldersRecursively: true);

foreach (var target in selection.Targets) { /* ... */ }
```

`SelectionResult` 클래스:

| 멤버 | 설명 |
|---|---|
| `List<ToolTarget> Targets` | 처리 대상 목록 |
| `int SelectedFolders` | 선택된 폴더 개수 (옵션이 꺼져 있어도 집계) |
| `int PrefabsFromFolders` | 폴더를 훑어서 찾아낸 프리팹 개수 |
| `bool HasIgnoredFolders` | 폴더를 골랐지만 옵션이 꺼져 무시된 상태 — 사용자에게 안내하기 좋음 |

`ToolTarget` 구조체:

| 멤버 | 설명 |
|---|---|
| `GameObject Root` | 씬 오브젝트, 또는 프리팹 에셋의 루트(읽기 전용) |
| `string AssetPath` | 프리팹 에셋일 때의 경로. 씬 오브젝트면 `null` |
| `bool IsPrefabAsset` | 프리팹 에셋인지 여부 |
| `bool FromFolder` | 직접 고른 게 아니라 폴더 검사로 찾아낸 대상인지 |
| `string DisplayName` | 표시용 이름 (프리팹은 경로, 씬 오브젝트는 이름) |

`Resolve`가 처리해 주는 것:

- Hierarchy 선택 → 씬 오브젝트 대상
- Project의 프리팹 선택 → 프리팹 에셋 대상 (프리팹의 하위 오브젝트를 골라도 루트 프리팹 전체가 대상)
- 프리팹 모드로 연 상태의 오브젝트 → 씬 오브젝트로 취급 (Undo 가능)
- 부모와 자식을 같이 선택한 경우 → 자식은 제외해 중복 처리 방지
- 폴더 선택 → (옵션이 켜져 있으면) **하위 폴더까지 포함한** 내부 프리팹 전부
- 폴더를 중첩 선택하거나 폴더+내부 프리팹을 같이 선택 → 중복 제거
- FBX 등 모델 에셋은 폴더 검사 결과에서 제외 (`.prefab` 파일만)

> `FromFolder`가 `true`인 대상은 사용자가 직접 고른 게 아니므로, 수정할 수 없는 에셋을 만났을 때
> 경고를 쏟아내지 말고 조용히 건너뛴 개수만 세는 편이 좋습니다. (`ColliderRemover.Report.SkippedPrefabs` 참고)

`Root`의 하위 계층 전체를 훑을 때는 **비활성 오브젝트 포함 여부를 꼭 인자로 넘기세요.**

```csharp
// 두 번째 인자 true = 비활성 오브젝트 포함
var renderers = target.Root.GetComponentsInChildren<MeshRenderer>(true);
```

## 4. 대상을 실제로 수정하기

### 씬 오브젝트 — Undo 기록

```csharp
Undo.IncrementCurrentGroup();
Undo.SetCurrentGroupName("My Tool Action");
int group = Undo.GetCurrentGroup();

Undo.RecordObject(component, "My Tool Action");   // 값 변경 전
component.someValue = 1;

Undo.DestroyObjectImmediate(component);           // 컴포넌트 삭제
Undo.AddComponent<BoxCollider>(go);               // 컴포넌트 추가

Undo.CollapseUndoOperations(group);               // 여러 작업을 Ctrl+Z 한 번으로
```

### 프리팹 에셋 — 파일 직접 수정

프리팹 에셋의 `Root`는 읽기 전용이라 그대로 고치면 안 됩니다. 내용을 임시 씬에 로드해 수정 후 저장합니다.

```csharp
// 수정 불가 에셋 먼저 걸러내기
if (PrefabUtility.GetPrefabAssetType(target.Root) == PrefabAssetType.Model) return; // FBX 등
if (PrefabUtility.IsPartOfImmutablePrefab(target.Root)) return;

var contents = PrefabUtility.LoadPrefabContents(target.AssetPath);
try
{
    // contents 와 그 하위를 자유롭게 수정
    bool changed = DoSomething(contents);

    if (changed)
    {
        PrefabUtility.SaveAsPrefabAsset(contents, target.AssetPath, out bool success);
        if (!success) Debug.LogWarning($"저장 실패: {target.AssetPath}");
    }
}
finally
{
    PrefabUtility.UnloadPrefabContents(contents);   // 반드시 해제
}
```

> 프리팹 에셋 수정은 **Undo가 되지 않습니다.** 실행 전 `EditorUtility.DisplayDialog`로 확인받는 것을 권장합니다.
> 여러 프리팹을 처리했다면 마지막에 `AssetDatabase.SaveAssets()`를 한 번 호출하세요.

### 컴포넌트 삭제 시 주의

다른 컴포넌트가 `[RequireComponent]`로 요구하는 컴포넌트는 삭제되지 않고 Unity 에러가 납니다.
`ColliderRemover.cs`의 `IsRequiredByOther` 방식(삭제 전 검사 후 경고로 수집)을 참고하세요.

## 5. 자주 쓰는 UI 조각

```csharp
// 설명 박스
EditorGUILayout.HelpBox("설명", MessageType.Info);   // Info / Warning / Error / None

// 옵션 토글 (값이 바뀌면 다시 계산)
using (var check = new EditorGUI.ChangeCheckScope())
{
    _option = EditorGUILayout.ToggleLeft("옵션", _option);
    if (check.changed) Refresh();
}

// 조건부 비활성 버튼
using (new EditorGUI.DisabledScope(_count == 0))
{
    if (GUILayout.Button("실행", GUILayout.Height(30f))) Execute();
}

// 확인 다이얼로그
if (!EditorUtility.DisplayDialog("제목", "정말 실행할까요?", "실행", "취소")) return;

// 스크롤 목록 (Vector2 필드 필요)
using (var scroll = new EditorGUILayout.ScrollViewScope(_scroll, GUILayout.MaxHeight(120f)))
{
    _scroll = scroll.scrollPosition;
    // ... 목록 그리기
}

// 진행률 표시 (대상이 많을 때)
EditorUtility.DisplayProgressBar("처리 중", target.DisplayName, i / (float)total);
EditorUtility.ClearProgressBar();   // try/finally 로 반드시 해제
```

## 6. 현재 등록된 탭

| Order | 탭 | UI | 로직 |
|---|---|---|---|
| 10 | 콜라이더 삭제 | `ColliderRemoverPage.cs` | `ColliderRemover.cs` |
| 20 | 라이팅 프리셋 | `LightingPresetPage.cs` | `LightingPresetApplier.cs` |
| 30 | 에셋 리플레이서 | `AssetReplacerPage.cs` | `AssetReplacerOps.cs` |
| 40 | 셰이더 감사 | `ShaderAuditPage.cs` | `ShaderAudit.cs` |
| 50 | 프리로드 매니페스트 | `PreloadManifestPage.cs` | `PreloadManifestBuilder.cs` |

탭이 아닌 채로 남아 있는 에디터 코드:

- `Assets/Editor/GameMarkerEditor.cs` — Timeline 마커의 `CustomTimelineEditor`. 창이 아니라 그리기 콜백이라 탭이 될 수 없습니다.
- `Assets/Editor/URPRealismSetupWindow.cs` — 자체 5탭 UI와 검색을 가진 독립 가이드 창(`Tools > URP 극사실주의 가이드`). 탭 안에 탭을 넣는 형태가 되어 분리해 둡니다.

### 탭과 메뉴를 함께 유지하는 경우

`ShaderAudit`과 `PreloadManifestBuilder`는 탭이 생긴 뒤에도 기존 `[MenuItem]`을 그대로 둡니다.
빌드 절차 문서와 다른 스크립트 주석이 메뉴 경로(`Tools > Build Preload Manifests` 등)를 가리키고 있기 때문입니다.
로직 클래스를 `static`으로 두고 탭과 메뉴가 같은 메서드를 부르게 하면 둘이 갈라지지 않습니다.

## 7. 참고할 코드

| 파일 | 참고할 내용 |
|---|---|
| `ColliderRemoverPage.cs` | 페이지 전체 구조 — 옵션 / 대상 미리보기 / 확인 / 결과 표시 |
| `ColliderRemover.cs` | 씬·프리팹 양쪽 처리, RequireComponent 검사, 경고 수집 |
| `LightingPresetApplier.cs` | 프리셋 배열을 데이터로 두고 UI가 순회하며 그리는 구조 |
| `AssetReplacerPage.cs` | 설정을 `EditorJsonUtility` + `EditorPrefs` 로 통째로 저장/복원 |
| `ShaderAuditPage.cs` | 긴 텍스트 결과를 스크롤·복사 가능하게 표시 |
| `AssetToolsSelection.cs` | 선택 항목 해석 |
| `AssetToolsWindow.cs` | 탭 자동 등록 및 레이아웃 |

새 기능을 만들 때는 **UI(`~Page.cs`)와 실제 동작 로직(`~.cs`)을 나눠 두면** 나중에 다른 탭이나 배치 스크립트에서 로직을 그대로 재사용할 수 있습니다.

### 씬 전용 동작은 `AssetToolsSelection` 을 쓰지 않아도 됩니다

`AssetReplacerPage` 는 `Selection.gameObjects` 를 직접 씁니다.
프리팹 인스턴스화·트랜스폼 랜덤화처럼 **씬 계층에서만 의미가 있는 동작**은 프리팹 에셋 대상이 성립하지 않기 때문입니다.
이럴 때는 헬퍼를 억지로 끼우지 말고, 탭 상단 HelpBox에 "씬 오브젝트만 대상"이라고 명시하세요.
